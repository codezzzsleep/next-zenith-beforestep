## 新仓库的用途

旧仓库同时包含多条实验路线、临时脚本和大量重复资产。新仓库重新按职责组织当前实现，只提取实际使用的模块；不以全量复制旧代码或重命名目录作为整理成果。旧仓库继续作为历史来源。

评委只收到本仓库。因此报告、源码、运行说明、关键资产、资产对比、技术版本演进和真实 Demo 必须在这里自足，不能要求评委到旧仓库补齐证据。源码按必交材料交付。

报告和 Demo 取材于真实运行，说明机器人面对的空间问题、Lux3D 对决策的作用、候选预演与实际执行结果。交互入口支持检查实验过程和比较策略，材料结论以工程证据为依据。

当不同渲染环境使实时截图与历史截图的字节不同，实时复用仍严格核对输入摘要。另提供明确标注的记录观测复现模式：使用保留的 RGB-D 与 Lux3D 输入，并核对机器人姿态和仿真时刻；当次实时渲染作为不同的观测保留。记录观测实验不能声称当次实时截图与旧输入逐字节相同。

## 训练模型与正式部署

v0.3默认部署经过完整实时任务验收的v4行为克隆权重，明确要求旧规则对照传入 `--controller-model rules`。推理失败不切换规则运动；停止制动不冒充学得动作。原始物理示教、目标增强、BC优化与实际PPO采样分开计数。指定目标变化用显式参数记录，物理场景和观测身份仍核对。

正式主任务采用(5.7,-0.5)终点，使新实时Lux几何的规划影响可以核对；原(8.5,0)成功与近岩石(5.4,-0.7)拒绝都保留。去掉生成的同模型对照也到达，结论限于候选参与决策与独立完成。保守观察姿态失败，以及v5/v6与分步姿态实验失败公开保留；未通过的改进不替换正式控制器。

同字节候选几何按输入/GLB/协议身份共享保存，每次预演和执行仍保留独立轨迹与运行身份。历史版本的原SHA、标签和发布附件保持冻结；新版本的模型与生成资产补充进资产清单。

主动观察的后续控制采用显式可选的训练朝向头与分步交接。其完整实时四眼任务和同首次记录观测的对照已通过原姿态门槛，相关训练、失败、输入、源码索引和实际轨迹见 [主动观察控制](observation-control.md)。新接近控制会改变首次截图，既有 Lux3D 资产仍必须核对输入身份，因此保持默认实时闭环与冻结发布可复现，新能力通过 `--pose-model` 开启。
