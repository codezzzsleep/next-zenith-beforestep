# 交付与证据保留决策

本项目为 Next Zenith 参加 Aholo 黑客松的作品，目标是让评委清楚理解、运行和体验机器人在盲区中利用 Lux3D 生成候选几何、先进行物理预演再行动的完整过程。

## 新仓库的用途

旧仓库同时包含多条实验路线、临时脚本和大量重复资产。新仓库重新按职责组织当前实现，只提取实际使用的模块；不以全量复制旧代码或重命名目录作为整理成果。旧仓库继续作为历史来源。

评委只收到本仓库。因此报告、源码、运行说明、关键资产、资产对比、技术版本演进和真实 Demo 必须在这里自足，不能要求评委到旧仓库补齐证据。源码按必交材料交付。

## 保留什么，为什么保留

| 内容 | 保留目的 |
| --- | --- |
| V6、V7、V8 与当前交付版的精选源码快照、冻结配置及关键结果 | 呈现问题、技术改动、效果和局限之间的因果关系 |
| 关键输入图、观察条件与输入摘要 | 说明模型实际看到了什么，使迭代可以比较 |
| 实际 Lux3D 原始 GLB、任务身份和资产摘要 | 证明核心资产来源并支持复查 |
| 配准、自检、准入结果及迭代后的几何 | 展示从生成到可执行候选的关键技术步骤 |
| 代表性被拒资产、失败结果与对比截图 | 展示真实技术边界，解释改进动机 |
| 预演、执行终态、真实运行画面和版本对比 | 让报告结论与可运行成果一致 |

不保留无关训练路线、成百上千的临时脚本、重复网格分片和无解释缓存。历史记录要经过选择和说明；拒绝的代表性候选不能因为结果不好而丢弃。

## 比较与展示的真实性

使用一致且冻结的自检门槛。新增样本必须单独标明输入来源、实验身份与原始资产，不能通过降低门槛制造成功。真值几何替身仅用于诊断，不作为 Lux3D 收益证据。结论区分已验证结果、未通过结果和仍待运行的实验。

Demo 包含真实运行画面。展示重点包括空间互动和机器人选择的趣味性，同时清楚呈现 Lux3D 在核心流程中的作用。

当不同渲染环境使实时截图与历史截图的字节不同，实时复用仍严格核对输入摘要。另提供明确标注的记录观测复现模式：使用保留的 RGB-D 与 Lux3D 输入，并核对机器人姿态和仿真时刻；当次实时渲染作为不同的观测保留。记录观测实验不能声称当次实时截图与旧输入逐字节相同。
