# 有效主场景的验收

旧 `stress_v8` 场景的真实 Lux3D 分支停下，没有完成通行。它作为困难反例保留，不能用“能安全停下”代替主展示成功，也不能仅凭报告和源码包齐全宣布项目完成。

新主场景要满足：

1. 起点与终点之间有明确障碍、阴影和可通行路线；独立真值物理执行只用于设计阶段验证可达性。
2. 使用新场景实际观测输入调用 Lux3D；输入、任务身份、原始 GLB、自检和配置都保存。保持原自检门槛，所有样本的结果公开。
3. 通过自检的真实候选改变占据图并参与实际物理预演；预演须完成且无碰撞。
4. 真实 Lux3D 生产链在独立物理场景中到达终点，不能用真值替身作为成果。
5. 对照策略采用同一场景、传感器和机器人；不通过让对照故意失灵展示收益。
6. 结果重复验证后才替换主作品页、视频、报告和源码包；旧场景、旧资产和旧发布保留为版本对比。

候选 `gate_passage_001` 保留月溪、岩壁和遮挡岩石，先验证单个盲区决策的完整通行链。它的原始配置在 `config/scenes/gate_passage_001.json`，验收前不称为成功主场景。

已验证结果：六个新真实任务中四个GLB成功，三个候选通过冻结自检，三份实际预演completed=true/collided=false，live Lux分支一眼76.50s到达、目标误差约8.7毫米；相同协议复跑验证。保守与直接走同场景也正常到达，不制造对照失败。
