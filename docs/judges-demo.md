# 评审 Demo 的可玩闭环与原片

项目定位：利用 Lux3D 的三维生成能力构建局部空间假设，支持导航与探索。
当前试玩从玩家自己的判断开始：在高石观察点停稳，看当前相机中的石缝，
留下“能过、绕开、拿不准”的初判，再选择自己开、空间想象、补看或停车。
辅助出发要求有效预演；手控在初判后独立开放。

脑内窗口显示真正提交过的原 RGB 图和官方 Aholo Viewer 中的原 GLB。
高石 A 的任务 5958948、5959025 使用同一张输入图，查看器按配准矩阵
保持相同世界朝向、照明和米制相机距离。高石 B 固定为任务 5958934。
原输入、任务号、GLB SHA、配准与核对来源见[候选清单](../site/judges-candidates.json)。
任务 5958642 是真实未通过原可见面核对的例子，只能查看；
其轮廓重合 0.4325 低于冻结门槛 0.7068。

Lux3D 返回物体级三维形状假设。已有 RGB-D、已知位姿与地形先验提供尺度和姿态，
系统核对原可见部分，将假设放回局部空间，MuJoCo 再计算运动和碰撞。
“先想后走的前额叶”比喻这一闭环，不表示 Lux3D 自带运动动力学或本局纯 RGB 导航。

青白边是已测表面，灰斜纹表示仍未知，琥珀色是准入候选新增占地。
灰线与金线来自同一规划器、同一起点；重合时如实说明。
投影余量采用 5 cm 栅格，不是实际接触测量；完整预演和独立执行分别记录。
当前第一相机与前视传感射线共用 M20 试玩观察位置，原 R1 相机输入保持不变。
主场景保留完整不透明扫描岩石、原纹理、月壤与斜阳，以自然遮挡限制第一眼。
决定前第三相机留在来路侧，俯视显示已知局部图。

本局补看只接收当前 MuJoCo 射线真实命中的障碍表面。
新增有效格或更高的有效表面才增加观测版本，重复相同观测不增加版本。
新版本进入规划、显示及候选世界的实测表面层，隐藏网格不直接填入规划图。
所选 A×B 组合至少一个有效世界且每个世界都实际走完，才能允许辅助出发。
取消、换选择或路线、出发前移动车体和有效新观测都会撤销旧许可。
途中接管记录为手控；偏离原走向后需要在当前停稳点重新预演。
路线到达矮坎前须完成自动对正并停稳，跨越按钮才开放。实际拒绝原因也写入本局导出事件。
探索检查点恢复本局观测、候选与决策，并清除旧许可和另一分支的后续统计。

局内结算与导出 JSON 读取实际初判、查看任务、选择变更、预演组合、

M20 为试玩外观；原研究保留 Go2W 条件。

## 复现

从 site/play.html 开始，桌面用 WASD / 方向键、空格，触屏用摇杆与刹车。
先选初判，Q 打开想象，切假设与走法，先试路再辅助出发。
高石后在矮坎前停稳，按高亮的 J / K / L 或触摸按钮完成四腿，
回到轮行并进入信标。E 补看，探索模式 R 恢复检查点。

    node tools/beforestep_mission/check_judges.mjs
    node tools/beforestep_mission/check_insight.mjs
    node tools/beforestep_mission/check_showcase.mjs
    node tools/beforestep_mission/check_experience.mjs
    node tools/beforestep_mission/check_m20_skin.mjs
    node tools/beforestep_mission/check_rock_surfaces.mjs
    node tools/beforestep_mission/check_worker_mission.mjs /tmp/judges-worker.json --judges --showcase

浏览器验收使用 tools/beforestep_mission/check_judges_browser.py，
提供 --url、--chromium、--out；--touch 为 390×844 触屏模拟，
--gpu 使用 NVIDIA EGL。公开验收不使用 --asset-root；
它只为开发录制提供 SHA 一致的资源镜像，不代表公开 CDN 加载速度。
素材规格、实际验证、章节与固定下载以 evidence/judges-demo/manifest.json 为准。
112 秒成片由导演制作，本项目交付原速操作与有来源的研究素材。
