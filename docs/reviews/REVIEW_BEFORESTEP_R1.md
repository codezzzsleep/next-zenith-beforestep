| 反事实：只信一份被拒绝的想象 | 见下 |

反事实的规则，事先定好：

- 对象是 B 第一眼被拒绝的全部候选，逐一单独用 `--trust T2=<id>` 跑，不挑选；

- 至少一份会撞，报告和视频里才可以说"自检挡住了会撞的想象"；一份都不撞，就如实写"自检偏保守"，不说它挡住了碰撞。

## 附录 A：§2.1 的参考实现

在 `src/beforestep/navigation/map.py` 里加入：

```python
F_HI = (3030 / 2) / np.tan(np.radians(35.0))   # 4040×3030 原图的竖直焦距（像素）
MIN_NATIVE_PX = 512                             # 与 config/protocol.json 的 min_native_px 一致；从配置读取更好


def target_px(cam_xy, target):
    """估计目标石头在原图里的像素高度：可见高度 × 焦距 ÷ 相机到它最近一格的距离。"""
    ix, iy = np.nonzero(target['cells'])
    d = float(np.min(np.hypot(XS[ix] - cam_xy[0], YS[iy] - cam_xy[1])))
    return target['H'] * F_HI / max(d, 0.3), d
```

```python
            cands.append((float(x), float(y), yaw, score, n, px if target is not None else None))
```

调用方需要的改动：

- `pipeline.py` 里调用 `choose_second_look` 的地方：
  - 想象的车、有被拒绝的石头时，传入 `target`；
  - `cells` 用这块石头的观测格；
  - `H` 用地图 `zmax` 在这块石头格子上的最大值，即可见点离路面的最高高度。
- 现有循环在 `n < 20` 时直接 `break`。有 `target` 时改成跳过（`continue`），否则一个看到格子少的达标点会挡住后面的候选。
- 在 `second_look_plan` 事件里记 `target_native_px_expected`。

单元测试，至少包括：

1. 固定一块石头和两个候选点，近的那个得到更大的像素估计；
2. 不到 0.8 m 的点被排在达标点之后；
3. 朝向对准石头格子的中心；
4. 有 `target` 时，排在第一的点的估计 ≥ 512 px（构造一个有达标点的地图）；
5. `target=None` 时，排序结果与改动前逐项一致（回归测试）。
