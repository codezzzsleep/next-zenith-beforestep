## 0. 为什么做这一轮

R1 把主线立住了：`stress_v8` 里保守车停车、乐观车碰撞、想象车到达。但它有三个弱点，本轮要补：

1. **只有一个场景、一次独立运行。** 评委会问“换个摆法还行吗”。要用一组事先定好的场景回答，结果全部报告。
2. **第二眼和自检没有真实数据支撑。** R1 真实运行一眼就到了，第二眼只经过替身验证；三份被拒候选的反事实 0/3 碰撞。场景多了，这两件事才有样本。
3. **不好玩。** 网页是回放，评委不能动手。比赛“趣味”占 25%，玩家评委占 30%。

本轮要交付的样子：

- 一个**预注册的月面场景组**：窄道、开阔月面散石、月坑边缘、坑加岩石四类，共 8–12 个小场景，每个都跑同样的五台车，出一张完整的结果总表。
- 一个**能玩的网页**：每个场景是一关，玩家先看机器人看到的画面，自己选怎么走，再揭晓真值和 Lux3D 的想象。
- 一个**自由摆石头的沙盒**：浏览器里拖石头，实时看三种策略怎么规划；摆好的场景可以导出，在本地跑完整真实链路。

“泛化”在本文里的意思是：**同一套冻结的流程，不为任何单个场景调参，在事先定好的多个场景上测出来的结果**。不是训练新模型。结果好坏都照实写。

### B2 场景生成器和候选池（不调 Lux3D）

写一个带种子的场景生成器 `ops/generate_suite_pool.py`，四个类别：

| 类别 | 内容 |
| --- | --- |
| F0 窄道 | 现有月溪加石堆的窄道，换岩石和摆放 |
| F1 开阔月面 | 没有月溪和石堆，散布 2–4 块岩石 |
| F2 月坑边缘 | 一到两个月坑收窄通路，坑沿有 1–2 块岩石 |
| F3 坑加岩石 | 月坑和散石混合 |

生成器的参数范围在跑之前写进 `docs/decisions.md` 并提交，约束是：

- 岩石只从 `assets/rocks` 的现有岩石库里取，高度 0.35–0.60 m；
- 太阳高度角 5°–12°（极区低角度），方位角可变；
- 起点到终点 8–12 m；
- 每个场景 1–3 块“目标岩石”（挡在路上、背面看不见的）。

每个类别先生成 12 个候选（种子 1–12），每个候选跑四次非 Lux 运行：保守、保守加 see-dark、乐观、真值检验。然后**只按这四个结果**分类：

| 分类 | 条件 | 含义 |
| --- | --- | --- |
| 决定性 | 真值检验到达，乐观碰撞，保守停车或用满 5 眼 | 看不见的那一面决定成败，而且有解 |
| 普通 | 真值检验到达，乐观也到达 | 想象不是必需的，用来检验“不需要时会不会帮倒忙” |
| 无解 | 真值检验到不了 | 场景本身不成立，丢弃 |

某个类别里决定性场景不足 2 个时，可以把该类别的池扩到 24 个（种子 13–24），只扩一次。还不够，可以调整生成器的参数范围后**整池重新生成**，把调整原因写进 `docs/decisions.md`。不准手工改单个场景。这一步始终不调 Lux3D，所以不构成挑结果。

全部候选的四次运行结果都保留，汇总成一张池统计表（每类多少决定性、多少普通、多少无解）。评委可以从这张表看出“想象决定成败”的情况有多常见。

### B7 结果总表

生成 `evidence/suite/summary.json` 和 `docs/suite.md`，每个场景一行：

- 类别、分类（决定性 / 普通）、种子；

### B8 结论怎么写，事先定好

## 5. 阶段 C：让评委能玩（11/14–11/16）

### C1 关卡模式（必做）

场景组的每个场景是一关。数据全部来自阶段 B 的真实运行，不新增实验。一关的流程：

1. **看**：显示机器人第一眼的真实画面，和带两种影子的俯视地图。不显示真值，不显示结果。
2. **选**：三个选项：直接走 / 多看几眼再走 / 想一想再走。
3. **走**：回放所选那台车在这个场景里的真实轨迹，到达、停车或碰撞都如实播放。
4. **揭晓**：
   - 真值俯视图，叠上 Lux3D 通过自检的候选占地和被拒的候选占地；
   - 三维查看：想象出的候选网格和真实岩石可以切换、旋转，重点看背面；
   - 三台车在这一关的结果并排显示。
5. **记分**：玩家的累计通过数，对比三种固定策略各自的通过数。
