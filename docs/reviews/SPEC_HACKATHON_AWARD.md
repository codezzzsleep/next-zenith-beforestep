## 0. 先定叙事：谁是主角

这个作品的唯一主角是 **Lux3D：一张平面照片，变成一整块立体石头，包括相机永远看不到的那一面**。网页和视频都围绕这一刻来组织。月球和影子不是主角，它们的作用只有一个——说明这件事为什么非做不可：

1. **事实（背景，短）**：机器人靠相机认路，相机给的是一张只拍到朝它那一面的平面照片；月球南极太阳几乎贴着地平线，没有大气散射，石头背光的那一面全黑，换几个角度看还是全黑。所以只看到一面、却要知道整块，在月面上绕不过去。（写出这一点就够了，不要展开成科普长文。）
2. **发现（我们的问题）**：机器人恰恰要从看不见的那一面旁边擦过去。用锚点实测当证据：把看不见的地方全当障碍的车看了五眼也规划不出路线；全当空地的车撞进黑影里的那块石头，原计划压进去 22 cm；能在黑影里测距的车三眼过去。
3. **核心（篇幅最大）**：Lux3D 把那张真实照片变成一整块三维石头。这是整页展示分量最大的一节。
4. **让想象可信（配角，为核心服务）**：拿看得见的部分核对（冻结自检）；多想几份；每一份都在独立世界里完整预演；心里没底就走到能看清的位置再看一眼。R3 的"两种影子分开处理"放在这里，作为一个安全细节讲，不当卖点。
5. **效果（全部回到事实）**：分两层写，先已知场景、再样本外。
   - 已知场景（R1 锚点 + R2 预注册 8 个决定性）：会想象的车 3 到达 3 停车 2 撞；保守 0 到达；乐观 8 撞；黑影测距 5 到达。锚点三台车里只有会想象的车安全到达，12 个想象世界预演全过、重放逐字节一致。被自检拒掉的想象里有 17 份信了会撞。
   - 样本外（R3 §3.4 五个留出场景，唯一的样本外证据，截至 2026-11-11 20:22 UTC 实测）：保守 0 到达；see-dark 3 到达；乐观 5 撞；**原想象 1 到达 2 停车 2 撞**；**修订想象 0 到达 5 停车 0 撞**。最终数字以 `build_r3_summary.py` 输出为准。
   - 结论一句话：Lux3D 的想象确实让车走到了没有想象就走不到的地方，但它的错误也会让车撞上；R3 的修订把碰撞消掉的同时也把这份收益消掉了。**这就是"有效，但不绝对"的确切边界**，照实写，不美化也不唱衰。
6. **局限与诚实**：锚点对 B 的三维间隙 47.541 mm、二维包络间隙 0，成功不稳健；R3 修订结果单独列，不覆盖原结果；样本外两次原想象碰撞（`F0_003`、`F3_006`）各写一句原因。
7. **自己玩**：关卡与沙盒。

两条硬性要求：**外行五秒被抓住**（第一屏就要让人看到"一张真实照片 → 一块可以转动的真实石头"），**内行五分钟能查证**（每一节可展开"怎么做到的"，里面是真实数字和证据链接）。所有画面用本仓库真实运行产生的资产，不许用抽象图形、示意图或新生成的假图冒充。

## 2.1 首页设计要求（写给首页制作者；Codex 只用它来验收集成结果）

按 §0 的主线，节序固定如下。每一节底部都可以展开"怎么做到的"，放真实数字与证据链接（内行入口），默认收起（外行体验）。

1. **第一屏（门面，必须五秒内被抓住）**：左侧是机器人真实拍到的那张照片；右侧是 Lux3D 由这张照片真实生成的 3D 石头，**可以拖动旋转**；转到背面时出现标注"这一面是 Lux3D 想出来的"。标题一句话，例如"机器人只拍到一面。Lux3D 把这一张照片，变成一整块石头。"下面一个按钮直接进入"自己玩"。禁止用抽象球体、示意图或新生成的图充当这一屏。
2. **背景（短，3–4 句 + 一张真实画面）**：月球南极太阳贴地平线、没有大气、背光面全黑，换角度也没用；所以只能从看得见的一面推断看不见的一面。不写科普长文。
3. **问题（我们的发现）**：机器人要从看不见的那一面旁边过。放锚点三台车的实测结果（停下的、撞上的、走过去的），每台车一句原因。
4. **核心（篇幅最大）**：Lux3D 从照片到整块石头的完整展示。至少包含
   - 同一块石头的多份真实生成结果并排（真实 GLB），可逐个旋转，标注任务 ID；
   - 真实石头与生成石头的叠合对比，转到背面看差多少（差多少就写多少，含 47.541 mm、二维包络 0、背面偏短 0.70 m/0.60 m 这类既有限量）。
5. **让想象可信（配角）**：六份想象哪些通过检查、哪些被拒（亮/暗两种状态，各写一句拒绝原因，如"轮廓对不上"）；把通过的想象以半透明方式叠回真实画面；12 个想象世界同时预演全部安全才出发；需要时走到能看清的位置再看一眼。
6. **效果（回到事实）**：8 个必须靠想象的场景成绩（保守 0 到达 / 乐观 8 撞 / 想象 3 到达 3 停车 2 撞 / 黑影测距 5 到达）、被自检拒掉但信了会撞的 17 份、两次碰撞各一句原因；结论一句"有效，但不绝对"。R3 修订结果单独一节，标明赛后修订，不覆盖原结果；oldv2 `F1_003` 碰撞仍须在 hero 或页脚可见。
7. **自己玩**：关卡与沙盒入口前置到这里。
8. **技术报告页**：把现有首页的表格、数字、审计内容**原样搬到 `report.html`**，一个链接跳过去，给内行查证。

硬性要求：

- 首屏 5 秒内必须出现"真实照片 + 可旋转的真实生成石头"；手机 390px 宽下同样成立，不出现横向滚动。
- 全站不得出现空占位（例如"视频位置：由负责人提供"）；视频未就绪前隐藏该区块，就绪后再显示。
- 单个 GLB 网页版控制在 2 MB 以内，首屏可交互在 2 秒内响应；控制台无报错。
- 只用仓库内真实资产（`assets/`、`evidence/`）；每张图每个模型都要能追到任务 ID 或证据路径，页面角落写出处。
- 3D 查看用仓库已经 vendored 的 `model-viewer`（three.js 内核）即可，不新增前端依赖。
- **不要做"拖动时太阳影子保持不变"这类交互**：真实观测里 DARK 标签会随视角变化（锚点 look1 3012 格 → look2 1592 格），只有几何上算出的无光区才不变，用它做动画等于把真值诊断包装成观测。影子一节只做静态对照 + 一行解释，把交互预算留给 Lux3D 那一节。
- 视觉标准：达到专业作品集的水准，不能出现"模板感"。判断标准是——把它和任何一份技术报告并排，第一眼不是同一类东西。

验收：桌面 1440 与手机 390 整页截图存 `evidence/`；外行测试（找一个没听过这个项目的人，看首屏 10 秒，让他说出这个项目在做什么）；控制台无报错；首屏资产加载时间记录在 RESULT。
