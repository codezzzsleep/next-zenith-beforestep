## 1. 为什么改方向

用户 11/12 晚的两条决定（原意）：

> 核心是用生成的三维盲区几何，帮助轮腿机器人判断“怎样通过”。我要求的学习与泛化能力可能不是必要的，自训导航模型可以降为可选项。而且必须发挥轮腿的特性，我感觉当前没有用到轮腿。
>
> 轮腿必须有一个强烈的动机，必须来自事实：不是“有轮腿更好”，而是“在某些场景下，没有轮腿就不行”。场景要在月球表面，要设计好。

另外用户确认：**Lux3D 额度还有两千多次，随便用。** 此前记忆里的 316/360 上限只属于前几轮，本轮上限见 §4。

负责人核对代码后确认用户的感觉属实：

- 仓库定义了高姿态 `STANCE_HIGH`（`src/beforestep/simulation/robot.py`），但全库没有任何地方使用它。主线控制始终把腿固定在 `BASE_POSE`，只靠轮速差行驶。
- 生成的整块石头最后只变成地图上“这一块不能走”。回答这个问题只需要一个背面轮廓，三维信息基本没用上。
- 现有判定把机器人任何部位碰到目标石头都算碰撞，越过石头在定义上就不可能。

所以这一轮只做一件事：**给轮腿一个非腿不可的任务，并让“跨不跨、从哪跨”这个判断只能由 Lux3D 生成的完整几何来回答。**

### 整个作品要讲的事（负责人定，所有材料以此为准）

作品按论文的顺序讲五件事。本轮实验是第五件里最重的一块，也是第三件的实证。

1. **背景**：月球南极有水冰，太阳贴着地平线，石头拖着长长的黑影；去那里的车越做越小；石头越小越多，小到轨道照片上看不出来，只能到了现场再面对。
2. **问题**：迈步之前必须知道石头的另一面。那一面被石头自己挡住，又落在黑影里，相机拍不到，换个位置也常常拍不到。
3. **洞察一**：对轮子来说，石头是障碍，知道它的轮廓就能绕开；对腿来说，石头是地形，要知道整块的形状才知道轮子往哪落、抬多高。**有了腿，完整的三维才从“有用”变成“必需”；有了完整的三维，腿才敢用。**
4. **洞察二**：生成的三维“看起来对”，不等于“踩上去对”。本项目 64 份通过了正面核对的真实 Lux3D 结果里，背面比真实短了 5 厘米以上的有 23 份，原方法四次碰撞中有三次是这个原因。所以生成结果不能直接用，要当成“假设”来检验。
5. **方法与效果**：BeforeStep 做四步——想象（一张照片生成多份整块石头）、对照（和看见的部分核对，对不上的拒掉）、预演（在每一份留下的想象里把动作完整做一遍）、迈步或停下。效果分三层证据：自检拦下了什么（R2/R3 已有）、绕行（R1 到 R3 已有）、跨越（本轮）。结论是“有效，但不绝对”，每一次出事都摆出来。

一句话版本，README 首段与报告摘要首段用它：

> 对轮子来说，石头是障碍，知道轮廓就能绕开；对腿来说，石头是地形，必须知道整块的形状。可整块石头有一半，机器人永远拍不到。BeforeStep 让 Lux3D 把那一半想象出来，再让轮腿机器人在迈步之前，把每一份想象都检验一遍、预演一遍。

R1 到 R3 的绕行实验全部保留，它们是“生成结果要先检查、先预演”的证据。本轮是同一条管线第一次用到整块形状，而不只是轮廓。

## 2. 场景：石门槛

### 2.1 事实动机

下面每一条都要能在页面和报告里给出出处。链接是负责人检索到的；**引用前打开原文核对，核对不上的那条就不用，不许凭印象改写。**

1. **月球南极太阳极低，背光面是测不到的黑影。** 两极的太阳最高只比地平线高约 1.5°（NASA SVS：<https://svs.gsfc.nasa.gov/4893>）。2025 年 3 月 IM-2 着陆器在南极附近侧翻，事后归因包括测高受干扰和南极的光照条件（<https://spacepolicyonline.com/news/im-2s-imperfect-landing-due-to-altimeter-interference-south-pole-lighting-conditions/>）。本项目的仿真太阳高度沿用 10°，比真实两极更宽松，这一点照实写。
2. **要进坑，就得过坑沿的石块带。** 新鲜撞击坑的坑沿上堆着被抛出来的石块（LROC “Boulder Fields”：<https://lroc.im-ldi.com/images/566>）。石块带绕坑一圈，没有“绕过去”这个选项。
3. **轮子过不了比自己半径高的坎。** 这一条不引文献，用 §5 在本项目自己的物理仿真里**实测**：这台车轮子半径 8.6 厘米，固定腿姿最高能滚过多高的石头，量出来是多少就写多少。对一台 40 厘米长的车，15 厘米的石头就是一堵墙。
4. **石头越小越多，而且事先看不到。** 月面石块的数量随尺寸减小而快速增多（嫦娥三号着陆区石块统计：<https://www.sciencedirect.com/science/article/abs/pii/S003206331500361X>）；月球轨道相机最好的分辨率是每像素 0.5 米（<https://ui.adsabs.harvard.edu/abs/2006epsc.conf..635H>），十几厘米的石头在轨道照片上不存在。车越小，挡路的石头相对它就越大、越多（Wilcox 1997，<https://ntrs.nasa.gov/citations/20060034957>，负责人未能打开原文，引用前必须核对）。
5. **真实任务已经给月球车装上了“腿”。** NASA 的南极找水车 VIPER 能把每个轮子单独抬起来，“几乎像脚一样”（<https://science.nasa.gov/mission/viper/rover-and-instruments/>）；JPL 的月面车 ATHLETE 平地用轮子滚，地形太糙时把每条肢当腿用（<https://www-robotics.jpl.nasa.gov/how-we-do-it/systems/the-athlete-rover/>）。
6. **看不见车底下的石头是真出过事的。** 2009 年“勇气号”陷在 Troy，车腹下有一块尖石顶着（<https://www.planetary.org/articles/11-12-mer-update>）。

要照实写的反面事实：VIPER 带了车灯（<https://www.nasa.gov/missions/artemis/clps/viper/viper-rover-will-get-driving-headlights/>），主动光源或激光雷达能缓解黑影；但被石头自己挡住的背面，任何传感器从正面都看不到。本项目的理由以“挡住”为主，“黑影”为辅。

### 2.2 场景构造

- **石门**：两块大石（高 0.6 米以上，沿用现有石墙素材，机器人绝不可能越过）之间留一个缺口，宽 0.9 到 1.1 米。缺口是到达目标的唯一通路。
- **门槛石 T**：一块矮石横在缺口里，两端压到大石脚下，两侧不留下任何大于 0.5 米（车宽）的空隙。T 的高度取在 §5 实测出的“必要带”内（轮行过不去、抬腿跨得过的高度区间）。
- **看不见的部分**：机器人在门前停下看一眼。相机离地只有约 0.32 米，T 的顶部棱线之后全被 T 自己挡住，再加上太阳的黑影，T 往后延伸多远、背面有没有更高的凸起，都测不到。
- **决定**：T 从正面看都差不多，但有的浅（抬腿跨得过），有的往后拖得很长或背面更高（跨不过）。**跨得过就跨，跨不过就停下**，停下是正确答案之一。
- **简化（照实写明）**：T 背后的落轮区没有别的石头；地面起伏沿用已知地形先验。机器人不能从生成的石头推断它背后的地面。

### 2.3 为什么这个场景同时需要轮腿和 Lux3D

| 没有它 | 结果 |
| --- | --- |
| 没有腿（固定腿姿） | 轮子滚不过 T，缺口对它永远是关着的 |
| 有腿但没有 Lux3D，只信看见的部分 | 把轮子落在“看见的石头后面”，而那里可能还是石头 |
| 有腿但没有 Lux3D，凡是没看见的都当危险 | 永远不敢跨 |
| 有腿也有 Lux3D | 知道整块石头多深多高，在想象里先跨一遍，再决定 |

这四行就是 §7 的四种方法。结果是否真的如此，由实验说了算，不许预设。

## 5. 第一步：轮腿能力实测（零付费，这是闸门）

### 5.1 机器人实际参数

负责人只读量得，供起步参考，**一切以你的实测为准**：

- 轮子半径 0.086 米；左右轮心距 0.384 米；前后轮心距约 0.387 米；车宽约 0.5 米。
- 大腿长 0.213 米，小腿到轮轴 0.271 米。关节范围：髋 ±1.047，大腿 −1.571 到 3.491，小腿 −2.723 到 −0.838（弧度）。
- 常规姿态 `STANCE`（大腿 0.85，小腿 −1.65）：机身中线离地约 0.22 米。高姿态 `STANCE_HIGH`（0.55，−1.05）：约 0.30 米。这是静态几何值，没有开过车。
- 整车 19.1 千克，月面重力 1.62，整车重约 31 牛。电机力矩上限：髋 23.7、大腿 23.7、小腿 45.4、轮 15（牛·米）。单条腿撑起整车绰绰有余，难点在重心是否落在支撑范围内，不在力气。
- 相机在机身前方 0.42 米处，与机身同高（常规姿态下离地约 0.32 米），俯角 24.83°。

### 5.2 新任务的判定（本轮所有方法共用）

每一步物理仿真都记录接触，分四类，逐场写入结果：

| 类别 | 定义 | 对结果的影响 |
| --- | --- | --- |
| 轮地接触 | 车轮与地面 | 正常 |
| 轮触石 | 车轮与门槛石 T 接触 | 单独记录；不算失败，但算“不干净” |
| 机身触石 | 车轮以外任何部位与任何石头接触 | 失败（碰撞） |
| 失稳 | 机身倾角超过现有翻倒阈值，或任何非车轮部位触地 | 失败 |

- **通过**：四个轮子全部越过 T，到达缺口后的目标点，全程没有机身触石、没有失稳。
- **干净通过**：通过，且全程没有轮触石。
- **卡住**：既没失败也没在时限内到达。
- **停下**：策略主动决定不跨，停在门前。
- 所有方法在距任何石头 0.5 米以内的行驶速度上限相同（建议 0.15 米/秒，定下后写进预注册）。固定腿姿也享有“轮触石不算失败”，让它有公平的机会滚过去。

### 5.3 三种能力，同一套试验坎

在平坦月壤上放横贯全宽的试验坎，高度 h 取 4、6、8、10、12、15、18、22 厘米，进深 d 取 10、20、30、40 厘米；每个组合以 0° 与 ±5° 三个接近角各试一次。再用 3 块现有石头素材缩放到相近尺寸各试一遍，因为真石头不是方块。

1. **轮行，固定常规姿态**：照常开过去。
2. **轮行，高姿态**：全程 `STANCE_HIGH` 开过去。
3. **逐轮跨越**（本轮要新做的动作）：
   - 机身先抬到足够高，让车腹能从坎的上方过去。
   - 一次只抬一个轮子，其余三个轮子支撑。抬腿前先用腿的关节把重心移进三轮支撑范围内。
   - 被抬起的轮子越过坎，落在坎后的地面上，再换下一个。四个轮子依次完成。
   - 动作是准静态的、有脚本的，输入只有四样：每条轮迹线上坎的近缘、远缘、最高点，以及横向过坎位置。输出抬轮高度与落轮位置。不用学习，不用优化器在线搜索。
   - 抬轮余量与落轮余量由本步实测定出，之后写进预注册，不再改。

### 5.4 产出与闸门

- 能力表 `evidence/crossing/calibration/capability.json`：每种能力在每个 (h, d) 上三次试验的结果与接触记录。
- **必要带**：固定常规姿态轮行 0/3 通过、且逐轮跨越在某个进深以内 3/3 通过的高度区间；同时给出每个高度下能跨的最大进深 `d_max`。高姿态轮行的结果并列写出：如果它也能过，那个高度就不属于必要带。
- **闸门**：必要带宽度不小于 5 厘米，且带内 `d_max` 不小于 15 厘米；3 块真石头素材中至少 2 块按真值参数干净通过。
- **闸门期限：11/14 12:00（北京时间）。** 到时没过，按 §12 第 1 条停下并报告实测数字。期限之前，动作怎么设计、调多少轮，由你决定。

## 6. 第二步：场景生成器、开发场景、预注册

### 6.1 生成器

`experimental/crossing/scene.py`：给定种子，生成一个石门槛场景（§2.2）。随机的东西：门槛石用哪块素材、缩放、朝向、横向位置，缺口宽度，太阳方位（高度固定 10°），停车观察点。门槛石的高度从必要带内取；进深的取值范围要**跨过 `d_max` 两侧**，使得一部分场景真的跨得过、一部分真的跨不过。

“真的跨不跨得过”不由构造决定，由 §7 的真值诊断在物理里跑出来。

### 6.2 开发场景（可以反复调）

用 4 个开发种子，对门槛石走完整的真实链路：停车观察 → 取图 → Lux3D 生成 → 自检准入 → 在每个准入的想象世界里预演跨越 → 在真实世界执行。

这一步要回答并定下来：

- 观察距离与姿态（门槛石比以往的石头小得多，在画面里要占够像素）；
- 低矮石头的生成结果能不能通过现有自检（阈值不许改；可以调的只有观察距离、裁图方式等输入侧的做法）；
- §7.2 决定规则里用到的余量。

开发场景的全部结果保留并公开，但不计入结论。

## 7. 第三步：锚点演示与测试

### 7.1 五列对照

| 代号 | 方法 | 说明 |
| --- | --- | --- |
| A | 没有腿 | 固定常规姿态，照常驶向缺口 |
| B | 有腿，只信看见的 | 远缘取“实际观测到的石头最远点”，最高点取观测到的最高点，直接执行 |
| C | 有腿，没看见的都当危险 | 背面未知就不跨。这是确定性的规则，直接列出结果，不必仿真 |
| D | 有腿 + Lux3D（本方法） | 见 §7.2 |
| E | 有腿 + 真值（诊断） | 用真实几何定参数。只用来标定“这一场本来跨不跨得过”，页面和报告始终标注“诊断，不是 Lux3D 的成绩” |

### 7.2 本方法的决定规则

1. 对门槛石的每一份**准入**的想象，在一组横向过坎位置上，沿两条轮迹线量出远缘和最高点。
2. 只保留“在所有准入想象里都处于能力范围内（高度在必要带上限以内、进深不超过 `d_max`、车腹过得去）”的横向位置。一个都没有，就**停下**。没有任何准入的想象，也停下。
3. 在保留的位置里选余量最大的一个。动作参数取所有准入想象的包络（最远的远缘、最高的最高点）。
4. 用这组参数在**每一个**准入的想象世界里完整预演一遍。任何一次预演没有干净通过，就停下。
5. 全部预演干净通过，才在真实世界执行。

### 7.3 运行

- **锚点**：负责人不指定具体种子。从开发场景里挑一场“B 会出事、D 干净通过”的作为演示锚点；如果开发场景里没有这样的，就挑 D 干净通过的一场，并照实说明 B 在这一场也没出事。锚点标注“演示用，不计入统计”。
- **测试**：12 个（或按补充规则追加后的）预注册场景，A、B、D、E 各在真实世界跑一次，D 另有各想象世界的预演。**只跑一次**，结果是什么就是什么。
- 每一场保存：场景定义、观测原图、上传给 Lux3D 的图、每个任务号与原始返回、准入/拒绝与各项指标、决定过程（每个横向位置在每份想象里的远缘与最高点）、预演与执行的完整轨迹（机身位姿 + 16 个关节角，不低于 20 Hz）、逐步接触记录、终态。
- 另外对每份想象，量出它的远缘与真实远缘之差（背面进深误差）、最高点与真实最高点之差，成表；并统计每个场景里各份准入想象对“跨/不跨”的结论是否一致。这是洞察二在矮石头上的实证。
- **洞察一的实证（零付费，必须做）**：在每个测试场景上，用现有的二维规划器（`N.plan`，占据用真实轮廓，即给它最好的条件）求一次去目标的路，记录“有路/无路”。预期全部无路；如果有路，说明该场景的缺口没堵死，这个场景作废并按种子顺序补一个。页面上要能说出这句话：只知道轮廓，这 N 个场景一个也过不去。
- 保全方式沿用 R3 的做法（完整包 + 公开清单）。

### 7.4 怎么报告

主表按“这一场本来跨不跨得过”（E 的结果）分两组：

- **跨得过的场**：每种方法干净通过几场、带轮触石通过几场、出事几场（机身触石/失稳/卡住）、停下几场（不必要的停）。
- **跨不过的场**：每种方法正确停下几场、出事几场。

预注册的达标说法（达不到也照实发布）：

1. A 在全部测试场景里通过 0 场；
2. D 没有任何机身触石或失稳；
3. D 在跨得过的场里干净通过不少于一半；
4. D 的出事场次少于 B，或者 D 的通过场次多于 C（C 恒为 0）。

样本只有十几场，报告里不写百分比，只写“几场里的几场”；不把它说成泛化结论。

## 11. 什么都不许凑

- 结果不好看不是停下的理由，也不是改规则的理由。预注册之后，判定、余量、种子、决定规则都不改。
- 每一次机身触石、失稳、卡住都保留完整记录并在页面上可见。
- 真值诊断（E）不得写成 Lux3D 的成绩；开发场景与锚点不得计入统计；十几场的结果不得写成“泛化”。
- 页面与文档里的所有数字由脚本从证据生成，不手写。
- 引用的事实必须对得上原文（§2.1）。

## 12. 只有这些情况才停下来

1. **闸门没过**：到 11/14 12:00，§5.4 的条件没有满足。停下，报告能力表的实测数字和卡在哪里。
2. **生成结果用不了**：开发场景里，在只调输入侧做法的前提下，门槛石没有任何一份想象通过现有自检，或者 4 个开发场景里本方法一次都没能做出“跨”的决定。停下，报告各项指标的实测值。
3. 需要改动冻结项（`src/`、准入阈值、R1/R2/R3、navigation_v1、Arena 已预注册内容）才能继续。
4. Lux3D 平台拒绝创建任务，或新增任务将超过 400。
5. 磁盘不足，且在不删证据的前提下无法释放。

除此之外的困难（动作要调、页面首次验收失败、某个辅助脚本出错）都自己解决并继续。
