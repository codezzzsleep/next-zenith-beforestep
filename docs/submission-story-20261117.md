# 先见一步：把照片变成机器人可以推演的局部空间

基于 Lux3D 的局部空间建模与轮腿机器人导航

## 参赛作品定位

BeforeStep 给轮腿机器人增加一条从二维观测到三维空间假设，再到行动判断的流程。机器人观察局部障碍，把普通照片交给 Lux3D 生成三维几何候选；系统将候选与已有观测对齐、核对，组合成用于通行判断的局部环境模型，规划路线并进行完整物理预演，再决定执行、补看或停车。

当前工作以月面岩石环境为受控仿真验证场景。它面向不完整观测下的局部通行问题，有已知地形与位姿条件；尚未验证任意未知环境中的完整自主探索。

## 完整故事

### 我们为什么做

机械狗进入陌生环境后，需要把看到的外观转成行动所需的空间信息：哪里有障碍，障碍延伸到哪里，通道能容纳多大的机器人，以及下一步怎样走。人能结合透视、遮挡、轮廓、纹理、光照和经验推断空间。相机记录图像，机器人需要感知与建模算法把这些信息变成可计算的几何。

已有测量能够提供可见表面的距离和形状，但遮挡仍会使空间信息不完整。月面低角度太阳和岩石遮挡为这个问题提供了一个具体测试环境：看见一部分，却需要在不完全知道另一部分形状的情况下判断通路。

### 我们发现了什么问题

只把观测到的表面当作全部障碍，可能低估障碍范围，导致碰撞；把所有未观测区域都视为障碍，又可能找不到通路。关键是如何形成有依据、能够验证的局部空间假设。

生成模型同样会出错：符合可见面不代表隐藏形状正确，完全没有被观察到的物体也可能不进入模型。因此，图片生成三维几何之后，还必须有观测核对、路线推演和独立执行验证。

### 我们做了什么

我们使用 Lux3D 的图生三维能力，根据普通 RGB 图片生成多份物体几何候选。Lux3D 返回的是三维网格；BeforeStep 负责把这些网格与观测对齐，放入环境坐标，并与已有观测和地形信息组合为局部环境假设。

这项工作体现了三维空间生成参与机器人感知的价值：生成模型的体积、形状和占地真正进入障碍计算，并改变机器人能否通过及怎样通过的判断。

当前系统仍使用可见区域的深度信息进行目标提取、尺寸和位置核对。深度负责已测部分，生成几何对未观测形状提出假设；两者组成当前验证过的方法。去掉深度需要另外实现尺度、位置和一致性估计，不能把现有结果改写成纯RGB导航。

### 机器人怎样使用这个空间

流程为：照片输入 → 三维候选 → 观测一致性核对 → 局部空间模型 → 路径规划 → 多世界完整物理预演 → 行动、补看或停止。

系统保留可见障碍、已知自由和未知区域的区别。每份通过核对的形状参与候选环境，机器人在这些环境中完整运行将要执行的路线；全部预演通过才支持执行，失败或信息不足则补看或停止。之后在独立仿真环境执行，比较预测和实际结果。

Lux3D 提供静态几何，MuJoCo 计算机器人运动与碰撞后果。这体现了建立内部空间表征、在模型中推演并据此选择行动的世界模型思路；当前并未训练一个新的端到端世界模型。

### 已有什么效果

R1同一窄道、同一机器人和控制器的实际对照如下，时间为仿真时钟，不包含云端生成与完整预演的墙钟耗时。

| 方法 | 观察次数 | 原运行结果 |
| --- | ---: | --- |
| 乐观：只按已有观测直接走 | 1 | 80.87 秒后碰撞 |
| 保守：未知空间视为阻塞 | 5 | 142.20 秒后停车 |
| Lux3D 几何假设与完整预演 | 1 | 112.84 秒安全到达 |

该次六份 A 候选与两份 B 候选组成十二个世界，完整预演都通过，随后独立执行到达。这支持生成几何在该观测条件下的导航价值。黑影中也可测深的对照同样到达，不能因此宣称生成模型比完整深度感知更有必要。

扩大到八个关键难场景，原方法为三到达、三停车、两碰撞；另五个留出中原方法一到达、两停车、两碰撞。四次原碰撞分别涉及未形成目标的障碍或背面被低估。原 R1/R2 的六十四份准入候选中，二十三份背面比真值短超过五厘米。

最终收紧未知区域通行规则后，十二个已知场景三到达、九停车、零碰撞；五个留出全部停车、零碰撞。修订减少了本批碰撞，同时增加停车，仍有安全与通行的权衡。

轮腿跨越是执行层的另一类能力：对已测清楚的低门槛，直接使用观测几何；在已测试的10、12、15厘米三个离散高度条件下，纯轮行零/九十通过、跨越二十四/二十四干净通过。它不证明每种门槛都需要生成模型。

### 最后交付了什么

作品已有可运行的机器人交互任务、真实 Lux3D 输入与模型、观测核对和完整预演、对照与失败记录、源码复现入口、作者发布的 B站视频与主报告 V5。当前连续 1080p 母片、补拍和五图见[交付目录](../evidence/judges-demo/README.md)，报告原文件见[版本索引](../reports/README.md)。观众可以驾驶机器人、旋转原始三维模型、选择候选世界并试路，再触发轮腿动作抵达目标。

全部运动与上述研究结果来自 MuJoCo 仿真。现有网页复用已经生成的真实模型，没有把当前游戏相机帧实时提交给 Lux3D；新的游戏成绩独立于 R1/R2/R3。 当前自然遮挡下先留下初判，再自选手控、想象、补看或停车；手控独立开放，完整预演许可只约束辅助路线。

## 可直接用于开场的介绍

我们希望让机械狗在进入未知局部环境时，能够把看到的外观变成行动所需的空间信息。BeforeStep 利用 Lux3D，把普通照片生成成三维几何候选，再结合实际观测建立局部环境假设，让机器人在这些空间中规划和预演路线，最后决定前进、补看还是停车。

我们以月面岩石通行为验证任务。生成的模型真实参与路线与碰撞计算，在一个窄道中帮助机器人只看一眼便安全到达，也在更多场景中暴露了隐藏形状猜错的风险。这份作品展示了从二维观测、三维空间建模到机器人行动的完整流程，并保留成功、失败与方法边界，供观众体验和复核。

## 用户提出说法的逐项核查

| 说法 | 判断与正式表达 |
| --- | --- |
| 人能从二维图像感知空间 | 成立；可靠教材明确单眼深度线索包括线性透视、遮挡和相对大小。明暗、材质和纹理需要结合条件解释，深浅颜色本身不能唯一确定距离。 |
| 机器人完全感知不到空间 | 不成立；机器人可以通过视觉学习与几何算法获得空间表征。应表述为相机图像需要感知、建模算法转换成行动可用的空间信息。 |
| Lux3D 图片输入需要深度 | 不需要；官方 img/imgs 接口接收普通图片。当前项目其他环节使用 RGB-D。 |
| Lux3D 直接返回局部环境地图 | 需修正；返回物体三维网格，BeforeStep 将其对齐、组合成可计算的局部环境假设。 |
| Lux3D 本身就是世界模型 | 查到的官方产品/API定位是3D资产/图生3D，与World生成/重建API互补，未取得明确把Lux3D自身定义为通用世界模型的原始技术材料。可以准确表述为“利用Lux3D进行局部世界建模，体现三维世界模型的空间生成与行动推演思路”。 |
| 三维世界模型一定要学习动作动力学 | 不能如此限定；World Labs把从图文生成可探索3D世界的Marble明确称为world model，说明当代三维世界模型也包括空间生成方向。该实例不等于证明Lux3D具有Marble的全部能力。 |
| 帮助探索未知空间 | 可作为应用目标；当前验证的是具有既定位姿和部分地形先验的不完整局部观测通行，尚未验证任意环境的自主探索。 |
| 比LiDAR/SLAM节能 | 尚未验证；测量、生成、配准、推演和总时长都应进入对照，暂不作为核心成果。 |

## M20 外观建议

云深处官方产品是山猫LYNX M20轮足机器人。官方公开模型仓库包含M20的MJCF、URDF与十七份分件网格，技术上有实施外观替换的资源。

保持原动力学和控制器，只做显示层适配，一般不需要训练；但是它并非直接覆盖文件即可完成。M20与现有Go2W的分件、关节轴、尺寸和连杆坐标需要映射，否则外观会与轮子落地、机身碰撞或跨越动作不一致。只换外观也不能称为M20实机或动力学验证。

限时参赛版本建议保留已经完成验证的Go2W，保证与已有报告、视频和实验身份一致。M20可作为后续独立外观演示，不影响当前主成果是否完整。本轮仅完成资源与技术可行性核查，没有更换机器人模型。
