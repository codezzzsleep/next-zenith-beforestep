# 项目书设计系统

固定设计语言，让内容和阅读任务决定组合。把项目材料当作事实来源，把组件当作可选的表达语法。先完整理解材料，再作设计；不要从旧作品里抽空内容得到一套固定槽位。

所有路径相对于本文件所在目录。脚本以 Python 3.10+ 运行。用用户的语言撰写文档。

## 一、先确定任务边界

1. 判断是 **新写 compose**、**忠实重排 reflow**，还是用户明确授权的摘要/改写。用户说“美化、重构排版”不等于授权删减内容。
2. 记录读者、文档用途、原材料范围、是否有硬性页数。没有页数要求时，由材料容量决定页数；不要默认压成 10 页。
3. 读取所有已提供材料，逐页看原 PDF。提取文字、图片、表格、图注、脚注、链接、数字、限制条件和计划状态。把原文件留作对照。
4. 只有会改变任务范围的缺项才询问用户。配色、构图和组件选择可自行判断并记录理由。

重排时先读 [内容保留](references/content-integrity.md)。需要选视觉形式时读 [选择规则](references/choose.md)。需要配置输入时读 [数据契约](references/data-contract.md)。

## 二、保留内容，再建立阅读结构

- 先建立 `inventory.json`，给需要保留的段落、图、表、注释等分配稳定 ID。
- 已有 PDF 可用 `scripts/source.py` 提取初始台账和原页参考图。**提取不等于完成核对**：逐页补齐矢量图、表格、图片蒙版、扫描文字和阅读顺序，再设置 `inventory_reviewed=true`。
- 默认用 `source` 组件逐字保留源单元；可以改变它所在页面与周围的布局。原文太长时，引擎分段续页，不缩字、不裁切。
- 用户授权改写后，设置 `document.allow_rewrite=true`，每个改写块注明 `source_ids` 和 `rewrite_note`。对数字、引文、口径与限制条件单独核对；自动检查不能证明改写语义无损。
- 未经授权不删除“重复、琐碎、不好看”的内容。确需省略时，用 `omissions` 逐项写原因与实际用户授权。
- 不把规划写成已完成，不把示意插画写成实录，不把外观相似当成数据相同。

允许一个主题连续多页，也允许同一页有几个彼此相关的小节。按材料选择“问题—方法—证据”等阅读顺序，但不强制任何项目具有同一套章节。

## 三、作一个可解释的设计方案

在工作目录写简短的 `plan.json`，记录：

- 文档用途、内容保留方式、页数约束。
- 配色、字体角色、网格、留白、一个来自项目主题的视觉特征。
- 封面候选至少 2 种、最终选择及素材依据。
- 每组主要信息的关系类型、组件/图表选择、备选方案和理由。
- 源单元到页面/附录的去向。后续分页可变，源单元 ID 不变。

使用 [设计语言](references/design-language.md) 的独立旋钮。预设只是起点，可以覆盖任一旋钮。不要因为文旅就必用山水、因为技术就必用数据封面。

## 四、按信息关系选组件

先问“读者要比较、查值、理解顺序，还是理解时间”，再选图。

| 关系 | 默认选择 | 关键条件 |
| --- | --- | --- |
| 类别的同口径数值比较 | bar / hbar / dot | 长标签或 >6 类优先横条；精确查值可直接用表 |
| 随时间变化 | line | 有真实时间或连续顺序；缺测不补点 |
| 部分与整体 | donut / stacked100 | 有同一整体与分母；不能把无关指标拼成占比 |
| 原始样本分布 | histogram / box | 只有均值不能画分布 |
| 两变量配对 | scatter | 不把相关写成因果 |
| 区间与不确定性 | range | 注明区间口径，不自动称作置信区间 |
| 前后差异、增减构成 | delta / slope / waterfall | 前后口径相同；瀑布项必须可加总 |
| 连续阶段转化 | funnel | 后阶段确实来自前阶段子集 |
| 多对象、多维度 | matrix / heatmap | 定性/混合值用矩阵；同尺度数值才用热图 |
| 顺序、分支、角色交接 | list / process / diagram | 2–3 简单动作可列表；4–7 步可流程；分支优先画拓扑 |
| 层级与归属 | layers / tree | 不凭层级添加流向或时间 |
| 连接与依赖 | architecture | 箭头有明确含义，复杂系统分总览与子图 |
| 事件与日期 | timeline | ≥3 个日期节点；只有阶段则用 roadmap |
| 起止任务与并行 | gantt | 有实际起止日期，且工期关系是阅读重点 |
| 精确查阅、规格、预算、条款 | table / definitions / p | 这些内容保留成表或文段往往更好 |

这些是 **15 类信息关系**，不是“所有数据只有 15 种”。数值、标签、日期、角色、拓扑可组合。阈值是默认排版策略，长标签、小图、复杂解释会让拆分更早发生。

详细阈值、反例、备选图表见 [选择规则](references/choose.md)。可运行 `scripts/choose.py` 生成可解释的建议；不要把程序建议当作对材料语义的判断。

组件分为 11 类：封面、页头、整页、布局、文字、数字、卡片、图像/图表、结构、时间、表格。用 `scripts/catalog.py --kind <类别>` 查实际字段、适用条件和示例。**代码注册表是组件名称的唯一来源。**

## 五、组装与生成

```bash
python3 scripts/doctor.py
python3 scripts/source.py 原报告.pdf 工作目录
# 逐页复核工作目录/inventory.json，补齐遗漏并确认 inventory_reviewed
python3 scripts/new_report.py 工作目录 --title 项目名 --preset research --inventory 工作目录/inventory.json
python3 scripts/catalog.py --kind cover
python3 scripts/engine.py 工作目录/spec.json 工作目录/report.pdf
```

新写文档可省略 `source.py` 和 `--inventory`，以用户提供的文字材料另建台账。没有原始 PDF 也不得补造数据。素材文件使用本地路径，引擎会内嵌到 HTML。

1. 编辑 `spec.json`，按内容组合组件，不复制整份案例。各页可更换页头；配色、字体与基本间距保持统一。
2. 图表在 `chart.data` 中声明；结构图在 `diagram.data` 中声明。也可独立运行 `charts.py`、`diagram.py` 和 `art.py` 生成 SVG。
3. 使用真实照片、截图、模型或原图承载证据。用 `art` 只作装饰与主题隐喻；不把插画放进每一页。
4. 让引擎测量容量并续页。可拆分原文、普通段落、列表、卡片组、时间线与表格；不可拆的大图或复合组件溢出时，改通栏、拆子图或换构图。
5. 保持正常正文字号至少 9.8pt，图注和辅助信息至少 8.2pt。不要为卡进页数自动缩字、截断句子或删条件。
6. 偏空时先判断留白是否服务阅读。需要补充说明时只从已有材料调入；不要用虚构数据、总结卡、装饰性图表灌满页面。

## 六、验证后交付

读取 `report.audit.json`，检查原文覆盖、逐字片段、事实引用、页数与边界。打开 `report.contact.jpg` 看全册节奏，再逐页查看 PDF 的小字、图表、页脚与续表。检查目录页码、真实图像的完整性，以及特殊字体是否缺字。发现问题后重新生成并查看最新版本。

- 自动检查通过不代表内容语义和视觉质量已通过。
- 图表须标单位、图例、出处与必要分母；补充真实限定条件，不制造置信带或评分。
- 原材料多时允许扩页或附录。用户要求更短时先说明取舍，再获得删减范围；不把“页数目标”解释成删除许可。
- 交付完成的 PDF。简要说明采用的设计方向、内容保留情况及确实存在的缺项。不要把实现参数和内部审计数据塞进项目正文。
