# 可组合的页面语法

这些是候选组合，不是章节槽位。按信息量增减块、换比例、拆续页。不要把任一配方当作“必含”。

| 页面任务 | 候选 A | 候选 B | 选择依据 |
| --- | --- | --- | --- |
| 定义项目 | 大标题 + 一段定义 + 真实产出 | 一段定义 + 关键概念定义列表 | 有无代表性视觉；概念是否需要解释 |
| 解释问题 | 场景图 + 2–3 个关键观察 | 连续正文 + 引文 + 已有数据表 | 观察是现场的、叙事的还是量化的 |
| 比较方案 | 多维矩阵 + 比较口径 | 单指标横条 + 两段条件说明 | 多维定性还是同口径单量 |
| 说明方法 | 通栏流程 + 各步条件 | 连续说明 + 分层图 + 原始截图 | 顺序、层级还是界面操作是重点 |
| 展示验证 | 数据图 + 方法/限制说明 | 精确结果表 + 证据图 + 原始记录链接 | 是否有可绘图的原始数值 |
| 展示作品 | 整页图版 + 图注 | 画廊 + 各图说明 | 一张复杂作品还是多个独立产出 |
| 说明失败 | 现象/原因/下一步卡 | 原始异常图 + 连续解释 | 有可定位的现象还是复合原因 |
| 回顾过程 | 纵向时间线 + 转折说明 | 主流程 + 决策矩阵 | 重点是何时发生还是为何决定 |
| 计划交付 | 甘特图 + 里程碑说明 | 阶段路线图 + 任务表 | 是否有真实起止日期 |
| 预算 | 明细表 + 计算口径 | 分类条图 + 完整明细附录 | 需要看金额构成还是逐项审计 |
| 术语/复现 | 定义列表 + 链接 | 连续步骤 + 规格表 | 概念查询还是执行顺序 |

## 整页组件的使用

- `page.opener`：大型章节入口。短文档不必为每章增加扉页。
- `page.statement`：一句可被材料支持的主要主张。不是用口号替代证据。
- `page.plate`：复杂原图、地图、界面总览；默认完整容纳原图。
- `page.editorial`：图像与较长叙事并置；长正文可改为常规页并续页。
- `page.contents`：有多个大章节时提供阅读路径，页码由最终分页解析。

## 留白与容量

不要用“每页固定 3–5 块”代替设计判断。封面、章节入口、图版可有大量有意留白；常规正文宜避免只有一小段的孤页。先考虑合页、调宽、换组合；不可通过新增无依据内容填满。

遇到溢出时按内容性质处理：

1. 连续文字、原文单元、列表、时间线与表格：允许续页，保留顺序与续页标题。
2. 图表：提高占用宽度，缩短外部冗长标题但保留完整字段说明，或按系列/类别拆图。
3. 拓扑结构：总览与子图分层，不缩成一张读不清的网络。
4. 封面：改变构图或将长说明移入开篇正文；不是把该说明从文档中删除。
5. 固定页数：正文概览 + 完整附录，或与用户明确删减范围。没有授权不省略。

## 叙事自由度

技术验证可以围绕问题—假设—方法—结果—边界展开，产品策划可以围绕人群—场景—体验—实现—交付展开，机构申报可遵循其规定的栏目。规定栏目优先。上述结构不是必选章节，不要求所有项目具有市场、失败、团队、四项能力或三个数字。

保留原有作品的语气。标题可用问题句、结论句或名词短语，选择最适合读者的形式，不强制把所有标题改为问句。
