# 内容保留与来源追踪

## 默认合同

用户说美化、重排、设计、重构版式时，保留完整信息是默认要求。样式参数可以变，事实、条件、例外、引文、未完成事项、出处、图表和图注不能因此消失。允许改变信息的分组与位置，不等于授权摘要。

区分三种工作：

| 类型 | 允许 | 需要额外依据 |
| --- | --- | --- |
| 忠实重排 | 换字体、配色、构图、顺序；原文与原图进入新页面 | 不删减、不改口径；所有源单元有去向 |
| 用户授权改写 | 改句式、合并表达、重新组织叙述 | 逐项来源、改写理由；对条件与语义人工复核 |
| 用户授权摘要 | 从全量材料选取重点 | 明确摘要范围和省略依据；不能声称保留全部内容 |

不要通过给 `required=false`、将单元 ID 塞进 `source_ids`、或把正文图像化来躲过检查。

## 建立信息台账

1. 保留原始文件与其 SHA256；记录文件页数和来源范围。
2. 提取初始文字块、原始图片和每页参考图。阅读顺序不必与程序提取顺序一致，应逐页复核。
3. 为每个需保留单元设置 ID：段落、表格、图、图注、脚注、引文、规格、链接均可独立成单元。
4. 补齐提取没有覆盖的内容：矢量图、蒙版合成图片、扫描文字、复杂表格、图例、坐标、跨页注释。
5. 不自动把页眉、引用、看似重复的条件当成无用信息。确属重复装饰时记录处理依据，正文仍要有唯一去向。
6. 扫描 PDF 无可提取文本时先做 OCR 或人工核对。不能将提取结果为空解释为原页为空。
7. 对每个源单元确定去向：正文、续页、附录、经用户授权改写、经用户授权省略。定好去向再设计页面。

## 逐字保留

使用 `{"type":"source","ids":["源单元ID"]}`。引擎从台账读取原字，不把星号、反引号等当成 Markdown。段落拆分只用于续页，所有片段按顺序拼接后必须与原文一致。

默认图像完整容纳。原始图很密时给它独立图版，配完整图注；不得裁去坐标、图例、单位或警告。图像缺失会阻止构建。提取出的图片如果缺蒙版、背景或图例，应从原页重新导出完整图，而不是宣称提取成功即证明原图完整。

## 改写与摘要

- 只在用户已授权的范围内启用 `document.allow_rewrite=true`。
- 每个改写块填写 `source_ids`，并用 `rewrite_note` 说明如何合并或改句式、什么条件必须保留。
- 逐项核对主体、范围、时间、分子/分母、否定词、比较对象、因果关系、可能性、未定事项和行动责任。
- 引文默认逐字保留。数据不因改写而四舍五入；若为读者使用展示值，原始精确值和口径仍有去向。
- 摘要的遗漏在交付说明中明确，不把摘要称为忠实重排。

自动检查只会提示改写单元需人工审核，不会对“意思差不多”出具无损保证。

## 数字、计划与证据

把数字与语境绑定：值、单位、时间、样本、统计口径、来源、状态。状态为 observed 已观察、planned 计划、estimated 估计。目标数不可冒充结果，示意数据不可进入事实台账当成实测。

已有 PDF 里的数字只说明它存在于原材料，不代表已对外部事实查证。用户要求核实或补充外部数据时另行查证并标出处。仅做忠实排版时不要擅自纠正数值、补日期或推算未知成本。

可计算的预算小计、合计必须保留组成项与计算规则。已知项合计应写“已知项小计”，未知费用单列，不把部分预算称成项目总预算。

## 交付核对

- 比较源台账数量、最终去向和原图，检查每个必保留单元。
- 查看 `audit.coverage.errors`、`warnings` 与 `semantic_review_required`，不能忽略黄色项后宣称完整无损。
- 将最终 PDF 与原始 PDF 逐页对照，不仅检查新封面或联系表。
- 说明真正无法核对的内容；不要在文档里虚构“全部已验证”的声明。
